# SQL Notes

SQL (Structured Query Language) is used to store, process, and analyze data based on user requirements using SQL queries.

DQL, DDL, DML, DCL, and TCL are important sub-languages used in data management and maintenance. Understanding the differences between them is crucial for managing and maintaining a database effectively.

We can interact with databases through five SQL sub-languages:

## 1. DQL – Data Query Language
- Definition: DQL stands for Data Query Language. It is used to retrieve data from databases.
- Purpose: Selecting, filtering, and sorting records from tables.
- Examples: SELECT * FROM Customer;  
  SELECT Name, Amount FROM Customer WHERE Amount > 20000 ORDER BY Amount DESC;

## 2. DDL – Data Definition Language
- Definition: DDL stands for Data Definition Language. It is used to define the structure of the database.
- Purpose: Create, modify, and delete database objects such as tables, indexes, and constraints.
- Examples: CREATE TABLE Customer (...);  
  ALTER TABLE Customer ADD COLUMN Age INT;  
  DROP TABLE Customer;

## 3. DML – Data Manipulation Language
- Definition: DML stands for Data Manipulation Language. It is used to manipulate data in a database.
- Purpose: Insert, update, and delete data from one or more tables.
- Examples: INSERT INTO Customer (Id, Name, Amount) VALUES (1, 'Rahul', 25000);  
  UPDATE Customer SET Amount = 30000 WHERE Id = 1;  
  DELETE FROM Customer WHERE Id = 1;

## 4. DCL – Data Control Language
- Definition: DCL stands for Data Control Language. It is used to control access to a database.
- Purpose: Grant and revoke permissions to users and roles. This is very important as you are liable to provide access to the right role or user.
- Examples: GRANT SELECT ON Customer TO user1;  
  REVOKE SELECT ON Customer FROM user1;
ALL PRIVILEGES → gives the user complete control (SELECT, INSERT, UPDATE, DELETE, etc.).
ex- GRANT ALL PRIVILEGES ON EMPLOYEES TO JOHN DOE;

## 5. TCL – Transaction Control Language
- Definition: TCL stands for Transaction Control Language. It is used to manage transactions in a database.
- Purpose: Ensure data consistency and integrity by controlling transactions.
- Examples: BEGIN TRANSACTION;  
  UPDATE Customer SET Amount = Amount - 5000 WHERE Id = 1;  

  COMMIT;  -- Save changes  
  ROLLBACK; -- Undo changes

Find & Remove Duplicates in SQL:

COUNT(*) → counts all rows, regardless of column values.

COUNT(column_name) → counts only rows where that column is NOT NULL.

SELECT emp_name, COUNT(*)
FROM employees
GROUP BY emp_name
HAVING COUNT(*) > 1;

Remove the duplicate value
DELETE 
FROM employees
WHERE emp_id NOT IN (
   SELECT MIN(emp_id)
   FROM employees
   GROUP BY emp_name
);

Running totals: - Write an SQL query to calculate the running total of salaries for employees, ordered by their employee ID.

SUM(salary) → adds salaries.

OVER → tells SQL to show the sum row by row instead of collapsing.

ORDER BY → defines the order in which the cumulative sum is built.

SELECT emp_name, emp_id, salary,
       SUM(salary) OVER (ORDER BY emp_id) AS running_total
FROM employees;

Question:  
In a Slowly Changing Dimension (SCD) Type 1 implementation, when a match is found between the source and target tables during a MERGE operation, how are the columns updated? Do the updates occur only when the new value is different from the existing one, or are the specified columns always overwritten regardless of whether the values are the same?

Answer:  
In SCD Type 1, the specified columns in the target table are always overwritten with the values from the source table whenever a match is found. The update does not check whether the new value is different from the existing one — it simply replaces the old data with the new data. If the values are identical, the update still executes, but the data remains unchanged. This approach ensures that the dimension table always reflects the most current information, but it does not preserve any historical data.
-------------------MERGE SYNTAX SCD TYPE 1:-----------------------------------------------
MERGE INTO target_table AS T
USING source_table AS S
ON T.emp_id = S.emp_id
WHEN MATCHED THEN
  UPDATE SET T.salary = S.salary, T.department = S.department
WHEN NOT MATCHED THEN
  INSERT (emp_id, emp_name, salary, department)
  VALUES (S.emp_id, S.emp_name, S.salary, S.department);

SCD TYPE 2:
MERGE INTO target_dim AS T
USING source_dim AS S
ON T.emp_id = S.emp_id AND T.is_current = TRUE
WHEN MATCHED AND T.salary <> S.salary THEN
  UPDATE SET T.is_current = FALSE, T.end_date = CURRENT_DATE()
WHEN NOT MATCHED THEN
  INSERT (emp_id, emp_name, salary, start_date, end_date, is_current)
  VALUES (S.emp_id, S.emp_name, S.salary, CURRENT_DATE(), NULL, TRUE);

SCD TYPE 3:
MERGE INTO employees_dim AS T
USING source AS S
ON T.emp_id = S.emp_id
WHEN MATCHED AND T.current_salary <> S.salary THEN

             T.current_salary = S.salary
